# Easy Visa — خطة التنفيذ (الإصدار الأول)

> وثيقة عمل حيّة. المرجع الأصلي: `Easy_Visa_Website_Developer_Reference.md`.

## 1. الهدف بجملة واحدة
منصة ثنائية اللغة (عربي افتراضي RTL / إنجليزي LTR) لاستقبال طلبات التأشيرات والسفر وتتبعها، مع لوحة تحكم يدير منها المالك كل شيء دون مطوّر.

## 2. التقنية المختارة ولماذا

| الطبقة | الاختيار | السبب |
|---|---|---|
| الواجهة + الخادم | **Next.js 16 (App Router) + TypeScript** | صفحات تُولَّد على الخادم (SEO + سرعة على الشبكات البطيئة) |
| لوحة التحكم / CMS | **Payload CMS 3** (مدمج داخل نفس تطبيق Next) | لوحة كاملة، صلاحيات، ترجمة حقول (ar/en)، رفع ملفات خاص، Hooks، Local API بدون شبكة |
| قاعدة البيانات | **PostgreSQL 16** | علائقية، موثوقة، نسخ احتياطي سهل (`pg_dump`) |
| الترجمة | **next-intl** + حقول Payload المترجمة | مسارات `/ar` و `/en`، `hreflang` صحيح |
| التنسيق | **Tailwind CSS v4** بخصائص منطقية (`ms-`/`me-`) | RTL/LTR بلا تكرار |
| الحركة | CSS + **Motion** بحدود ضيقة | لحظة حركة واحدة مدروسة، احترام `prefers-reduced-motion` |
| النماذج | **react-hook-form + zod** (نفس المخطط على العميل والخادم) | تحقق مزدوج ورسائل بلغتين |
| الملفات | مجموعة Payload خاصة خارج `public` → S3 خاص في الإنتاج | لا روابط عامة للجوازات |
| الاختبار | **Vitest** (منطق) + **Playwright** (رحلات كاملة) | |
| الاستضافة المقترحة | VPS (Hetzner/DigitalOcean) + Docker + Caddy (HTTPS تلقائي) | تكلفة منخفضة، ملكية كاملة للعميل |

## 3. خريطة الموقع

```
/ar (افتراضي)  و  /en
├── /                       الرئيسية
├── /services               كل الخدمات (تأشيرات + سفر)
│   ├── /services/visas     فئة التأشيرات
│   ├── /services/travel    فئة السفر والحجوزات
│   └── /services/[slug]    تفاصيل خدمة + زر الطلب + واتساب
├── /request/[slug]         نموذج الطلب الخاص بالخدمة (خطوات)
├── /request/success        تأكيد + رقم المرجع + متابعة على واتساب
├── /track                  تتبع الطلب (مرجع + آخر 4 أرقام من الهاتف)
├── /offers  و /offers/[slug]
├── /about
├── /contact
├── /faq
├── /privacy  و  /terms
└── /admin                  لوحة تحكم Payload (عربية RTL)
```

## 4. نموذج البيانات (Payload)

**Collections**
- `users` — الدور: `owner` | `staff`، قفل بعد محاولات فاشلة.
- `media` — صور عامة (خدمات/عروض) مع أحجام WebP/AVIF.
- `service-categories` — visas / travel (مترجمة).
- `services` — الاسم، الملخص، الوصف (Rich text)، المتطلبات، الملاحظات، أسئلة شائعة، السعر (اختياري/نطاق/«عرض سعر») + العملة، متاح؟، مميز؟، الترتيب، **حقول النموذج القابلة للتهيئة**، رقم واتساب المسؤول، الحالة (مسودة/منشور/مؤرشف).
- `destinations` — دول الوجهات (قابلة للإضافة من اللوحة).
- `offers` — بتواريخ بداية/نهاية، الحالة تُحسب تلقائياً (مجدول/نشط/منتهي).
- `customers` — الاسم + الهاتف (فريد) + الطلبات.
- `requests` — `reference` (EV-26-XXXXXX غير قابل للتخمين)، الخدمة، العميل، البيانات المقدَّمة (JSON بحسب حقول الخدمة)، المصدر (website/whatsapp/phone/walk-in)، الحالة، الموظف المسؤول، رسالة للعميل، **سجل الحالات**، **ملاحظات داخلية** (لا تظهر للعميل أبداً)، **محاولات التواصل**.
- `request-documents` — ملفات خاصة، تحقق من نوع الملف الحقيقي (magic bytes)، حد للحجم، وصول للموظفين فقط.
- `faqs`, `audit-logs`.

**Globals**: `site-settings` (أرقام الهاتف/واتساب المتعددة، روابط التواصل، العملات، نصوص الموافقة)، `homepage`، `about-page`، `legal-pages`.

**سير الحالات**: جديد → قيد المراجعة → بانتظار معلومات العميل → قيد التنفيذ → مكتمل / مرفوض / ملغي. كل تغيير يُسجَّل (من، متى، رسالة للعميل، ملاحظة داخلية).

## 5. تحسينات مقترحة خاصة بالسوق اليمني
1. **أرقام عربية/هندية**: قبول `٠١٢٣` وتحويلها تلقائياً في الهاتف ورقم المرجع.
2. **هواتف اليمن والسعودية**: تحقق ذكي لـ `+967` و `+966` (أقارب في المملكة).
3. **التاريخ الهجري بجانب الميلادي** في نماذج العمرة (عبر `Intl` بدون مكتبات).
4. **رقمان لواتساب** (كما في البروشور) مع توجيه كل خدمة لرقمها، ورسالة واتساب مُعبّأة تتضمن رقم المرجع.
5. **ضغط الصور على الجوال قبل الرفع** (صور الجواز 5MB → ~400KB) لتوفير الباقة.
6. **حفظ مسودة النموذج تلقائياً** محلياً عند انقطاع الإنترنت/الكهرباء.
7. **زر "إشعار العميل عبر واتساب"** في اللوحة: يفتح واتساب برسالة جاهزة بحالة الطلب (بدون ادعاء إرسال آلي).
8. **إيصال قابل للطباعة/الحفظ** لرقم المرجع.
9. **صفحات خفيفة جداً**: بدون فيديو، صور AVIF، خطوط مقسّمة، JS أقل ما يمكن في الصفحات العامة.
10. **قائمة مستندات تفاعلية** لكل خدمة يحددها المالك.

## 6. نظام التصميم

**الفكرة**: لغة "بطاقة الصعود للطائرة" (Boarding pass) — هي الشيء المميز الوحيد: بطاقة التتبع في الواجهة، صفحة التأكيد، والإيصال تأخذ شكل تذكرة بحافة مثقّبة ورمز مرجعي. باقي الصفحة هادئة ومنضبطة.

| الاسم | القيمة | الدور |
|---|---|---|
| Navy | `#12306B` | لون العلامة الأساسي (من الشعار) |
| Night | `#0B1D45` | خلفيات داكنة، تذييل |
| Gold | `#C9962E` | تمييز، أزرار ثانوية، خط رحلة |
| Sand gold | `#F2E3BC` | خلفيات تمييز خفيفة |
| Mist | `#F4F6FB` | خلفية الأقسام (باردة، ليست كريمية) |
| Ink | `#16213B` | النصوص |

**الخطوط**: `Readex Pro` للعناوين (هندسي يشبه خط الشعار، عربي+لاتيني)، `IBM Plex Sans Arabic` للنص.
**الخدمات**: تُعرض كـ "لوحة مغادرة" (Departures board) — صفوف واضحة بدل بطاقات متطابقة.
**الحركة**: لحظة واحدة — خط الرحلة الذهبي يُرسم في الواجهة عند التحميل. تفاعلات الأزرار والنماذج فقط.
**ممنوعات**: عدادات وهمية، تقييمات مزيفة، شعارات شركاء، ادعاءات ضمان التأشيرة.

## 7. الأمان والخصوصية
HTTPS، كلمات مرور مشفرة (Payload)، قفل الحساب، صلاحيات حسب الدور، تحديد معدل الطلبات للتتبع والنماذج، تحقق خادمي بـ zod، ملفات خاصة بروابط مصرّح بها فقط، سجل تدقيق، أسرار في `.env` فقط، نسخ احتياطي يومي لـ Postgres + الملفات.

## 8.1 الحالة الحالية (نوفمبر 2026)
اكتملت كل المراحل، وأُضيف فوق الإصدار الأول:
- **الرحلات المتاحة** (باصات، طيران، باقات عمرة) مع الشركات والمزوّدين، والمقاعد تُحسب تلقائياً، والحجز يُرفض عند الامتلاء.
- **الدفع:** مبلغ على الطلب، حسابات بنكية من الإعدادات، رفع إيصال التحويل، رابط دفع بالبطاقة عبر بوابة آمنة، دفع في المكتب، وتأكيد من الموظف.
- **طلباتي** للضيوف دون حساب (محفوظة على الجهاز)، و**نموذج تواصل** يصل إلى اللوحة.
- **إحصاءات زيارات** دون كوكيز، و**صفحة تقارير** مع تصدير Excel.
- **لوحة تحكم بتصميم جديد** بالكحلي والذهبي، تدعم الجوال والعربية والوضع الليلي.
- **اختبارات:** 26 اختبار وحدة و7 اختبارات متصفح، وبناء الإنتاج ناجح.
- **ملفات النشر:** Docker وCaddy ونسخ احتياطي يومي، إضافة إلى `docs/DEPLOYMENT.md` و`docs/ADMIN-GUIDE.md`.
